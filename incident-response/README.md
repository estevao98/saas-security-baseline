# Resposta a Incidentes

## Objetivo

Organizar referências para preparação, triagem, resposta, comunicação, evidências e aprendizado de incidentes.

Não registrar aqui incidentes reais, indicadores sensíveis, timeline forense, dados pessoais, clientes, tenants, segredos, logs crus, payloads ou comunicações formais.

## Como Usar

1. Use ID opaco para suspeita ou incidente.
2. Preserve evidência crua fora do Git.
3. Acione owners competentes por canal restrito.
4. Publique no repositório apenas postmortem sanitizado, quando aprovado.

## Pendências

- Canal privado real, SLAs, plantão, comunicação externa e obrigações legais são definidos no SaaS consumidor.
